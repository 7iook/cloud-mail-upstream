## Cascade SQL (same batch, this order)

idsJson = JSON.stringify(normalized ids). One bind param per json_each(?). Never expand IN (?, ?, …).

1) Revoke affected shares with no survivors — MUST go through prepareRevoke(c, whereSql, [idsJson, idsJson, idsJson]) so AND status='ACTIVE' + RETURNING stay SSOT.

whereSql (recon §3.2-①):

  (
    EXISTS (SELECT 1 FROM mail_share_binding b
            WHERE b.share_id = mail_share.share_id
              AND b.account_id IN (SELECT value FROM json_each(?)))
    OR (
      NOT EXISTS (SELECT 1 FROM mail_share_binding b WHERE b.share_id = mail_share.share_id)
      AND mail_share.account_id IN (SELECT value FROM json_each(?))
    )
  )
  AND NOT EXISTS (SELECT 1 FROM mail_share_binding b
                  WHERE b.share_id = mail_share.share_id
                    AND b.account_id NOT IN (SELECT value FROM json_each(?)))

2) Resync primary account_id / window_start_email_id excluding the dying set. EXISTS(survivor) + account_id > 0. Never write 0/NULL. Do not reuse/modify syncPrimaryAccountId; new helper. SQL = recon §3.2-②.

3) DELETE FROM mail_share_binding WHERE account_id IN (SELECT value FROM json_each(?)) RETURNING share_id, account_id

Order: 1 then 2 then 3. 1 and 2 must run before DELETE because they read dying rows.

Hard facts to comment in the function:
- Cascade always runs while the account row is still alive / still NORMAL. NEVER predicate on "account already deleted". Predicate is only accountId ∈ incoming set.
- No try/catch. Fail-closed.
- Keep empty-ids early return. Empty json_each + NOT IN is universally true and would revoke every zero-binding ACTIVE share.

Return: { revoked, unbound }. revoked = statement 1 meta.changes (shares set REVOKED), NOT "affected shares". unbound = deleted binding count. Callers ignore extras.

Events: reuse SHARE_EVENT.BINDING_CASCADE via logShareEvent. One line per affected share, not per binding. Fields like { shareId, reason: 'account_deleted', removedBindings: n, revoked: true|false }. No email / sec / authKey / token / IP. Do not pass event/ts (envelope overwrites them). Do not add SHARE_EVENT names (closed toEqual of 6).
