## Implementation contract

share-mail-service.listForBinding(c, ctx, bindingId, cursor, limit, deps):
  repo.listForBinding then same attach/project as list(). Unknown / foreign binding → [] (no existence leak).

share-api GET /share/mails:
  bindingId absent/'' → list(); else listForBinding. "0" is a real id.

request/share.js:
  listParams also copies bindingId when != null && !== ''
  getShareMailboxesStatus({ sessionToken, signal }) → GET /share/mailboxes/status
  listShareMails may pass bindingId

status-watermark.js: pure functions per recon §3. bindingId 0 serializes as "0".
hasNew after reconcile uses stored keys. Advance is Math.max, never backwards.

index.vue:
- Extend applyShareConfig to also read shareType (default 'single') and mailboxes[].
  After mailboxes change, pick activeBinding if null: mailboxes[0].bindingId.
  Reset shareType/mailboxes/activeBinding/watermarks at bootstrap start (same place as otpEnabled=true).
  Do not read autoRefresh / refreshIntervalMs / expiresAt.
- visibleMails filters mails by activeBinding when isMulti; else all.
  listMails / selectedMail / ShareOtpCard :mails="visibleMails" :selected="selectedMail" :enabled="otpEnabled"
- Native tablist only when isMulti (shareType==='multi' && mailboxes.length>1).
  Hooks: data-share-tabs, data-share-tab="<id>", data-share-tab-badge
  tx('shareVisitMailboxes','Mailboxes') / tx('shareVisitNewMail','New mail') — do not edit i18n files.
- pollTick injected as listShareMails: 1 status, reconcile+writeWatermarks, syncMailboxesFromStatus (AC-EDGE-04: drop removed boxes; if active gone, fall back to first), then 1 mails with bindingId=activeBinding (or omit if still null), no cursor. After success, advance watermark to max mailId in that page for the active binding.
- selectTab: set activeBinding, clear selectedId, if no mails for that binding then listShareMails({sessionToken, bindingId, limit, signal}) and mergeMails.
- beginMailbox: if activeBinding != null, pass it; keep cursor catch-up for older pages of that binding.
- sessionStorage restore still has no mailboxes until first status tick — pollTick hydrates via syncMailboxesFromStatus. Do not persist mailboxes in sessionStorage.
- Do not clear share:status:<lid> on exit (T-26 credential cleanup only).
- No el-tabs. Selected tab: aria-selected + 2px bottom border #0969da. Badge is a dot + aria-label, not a count.

useSharePolling.spec.js: one new it() — injected fetcher that itself calls a status mock then maybe mails; each tick status exactly 1; do not change the existing 6.

index.spec.js new tests (names = scenarios):
